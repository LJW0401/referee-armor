# ESP32 装甲模块串口通信协议

本文定义 PC 上位机与 ESP32-C3 下位机之间的 USB CDC 串口协议。它是协议的唯一规范；固件和上位机必须以本文为准实现。

## 目标与边界

- 上位机在用户选择串口后，以一次可关联的握手确认目标设备，再读取当前状态。
- 支持后续增加 LED 控制、去皮和标定命令，而不改变已有帧格式。
- 协议只运行在 ESP32-C3 原生 USB CDC 的 `Serial` 上，不涉及下载器私有协议。
- 本协议不提供认证或加密；USB 接入者拥有设备控制权限。

## 串口与会话

串口参数固定为 `115200 8N1`，无流控。ESP32 重启或固件更新后，USB 设备可能重新枚举，上位机必须将其视为断开连接。

固件的该串口只能输出本协议帧，禁止混入 `Serial.print` 日志或调试文本。调试日志必须关闭或使用其他接口，否则上位机无法可靠分帧。

上位机打开端口后应等待 500 ms、丢弃期间收到的字节，然后发送 `GET_DEVICE_INFO`。这个命令是幂等的：若 500 ms 内没有收到合法响应，上位机最多再发送两次；三次都失败即连接失败。写操作不得自动重试。

一次连接中的请求必须串行：在收到当前请求的成功或错误响应前，不得发送下一请求。下位机必须在 200 ms 内响应可立即完成的查询命令；需要更久时间的将来命令应使用异步任务模型，而非阻塞串口处理。

## 帧编码

每帧先生成“原始帧”，以 Consistent Overhead Byte Stuffing（COBS）编码，再追加单个 `0x00` 作为帧结束符。空帧（连续两个 `0x00`）必须丢弃。

COBS 解码后的原始帧采用小端字节序：

| 偏移 | 字段 | 类型 | 说明 |
| --- | --- | --- | --- |
| 0 | `version` | `u8` | 协议版本，当前固定为 `1` |
| 1 | `type` | `u8` | 帧类型 |
| 2 | `sequence` | `u16` | 上位机递增请求序号；响应必须原样回显 |
| 4 | `payload_length` | `u16` | 负载长度，范围 `0..192` |
| 6 | `payload` | bytes | 命令或响应数据 |
| 6 + N | `crc16` | `u16` | 前述所有字节的 CRC，不包含自身 |

CRC 使用 **CRC-16/CCITT-FALSE**：多项式 `0x1021`、初值 `0xFFFF`、不反射输入输出、结果异或 `0x0000`。`payload_length` 与实际长度不符、版本不支持、COBS 解码失败、CRC 不匹配或原始帧超过 200 字节时，接收方必须丢弃该帧；不能执行其中的命令。

`sequence` 从 `1` 开始递增，到 `65535` 后回绕为 `1`；`0` 保留。上位机只接受与未完成请求具有相同 `sequence` 的响应。任何不匹配的响应都必须丢弃并记录为协议错误。

## 帧类型与命令

请求帧 `type` 为命令号；成功响应为 `命令号 | 0x80`；错误响应为 `0xFF`。本版本定义如下：

| 请求 | 成功响应 | 名称 | 负载 |
| --- | --- | --- | --- |
| `0x01` | `0x81` | `GET_DEVICE_INFO` | 请求携带上位机随机数；响应携带设备身份 |
| `0x02` | `0x82` | `GET_STATUS` | 请求为空；响应携带当前运行状态 |
| `0x10` | `0x90` | `SET_LED_COLOR` | 请求携带同一颜色的 RGB 值；响应为空 |

尚未定义的命令号必须返回错误 `UNSUPPORTED_COMMAND`，不得静默忽略。

### `GET_DEVICE_INFO`（建立连接）

请求负载固定为 4 字节 `client_nonce`（`u32`）。上位机每次打开端口必须生成新的随机值。

成功响应负载：

| 偏移 | 字段 | 类型 | 说明 |
| --- | --- | --- | --- |
| 0 | `client_nonce` | `u32` | 必须等于请求值 |
| 4 | `device_id` | `u64` | 芯片 MAC 转为无符号 64 位值；全局唯一设备标识 |
| 12 | `protocol_version` | `u8` | 当前为 `1` |
| 13 | `firmware_major` | `u8` | 固件主版本 |
| 14 | `firmware_minor` | `u8` | 固件次版本 |
| 15 | `firmware_patch` | `u8` | 固件补丁版本 |
| 16 | `capabilities` | `u32` | 支持能力位图 |

仅当响应 `sequence`、帧类型、`client_nonce` 和 `protocol_version` 均匹配时，上位机才可标记为“已连接到 ESP32”。`device_id` 用于在 UI 中识别曾连接过的设备，不能仅依赖易变化的 COM 端口号。

能力位定义：`bit 0` = 支持 WS2812 控制，`bit 1` = 支持 HX711，`bit 2` = 支持去皮，`bit 3` = 支持重量标定。未声明的位必须为 `0`。

### `GET_STATUS`

仅在握手成功后允许发送。请求负载长度为 `0`。

成功响应负载固定为 20 字节：

| 偏移 | 字段 | 类型 | 说明 |
| --- | --- | --- | --- |
| 0 | `status_schema` | `u8` | 当前固定为 `1` |
| 1 | `health_flags` | `u16` | 设备健康与可用性位图 |
| 3 | `uptime_ms` | `u32` | 本次启动后毫秒数，允许回绕 |
| 7 | `weight_mg` | `i32` | 已滤波净重，单位毫克；无有效值时为 `INT32_MIN` |
| 11 | `sample_age_ms` | `u32` | 最新有效 HX711 样本距当前的时长；无有效样本时为 `UINT32_MAX` |
| 15 | `led_count` | `u8` | 已配置的 WS2812 灯珠数，未配置为 `0` |
| 16 | `active_led_effect` | `u8` | 当前灯效编号，`0` 表示关闭/静态 |
| 17 | `reserved` | 3 bytes | 当前必须为 `0`，接收方忽略 |

`health_flags`：`bit 0` = HX711 已初始化，`bit 1` = 已取得有效重量，`bit 2` = HX711 读取超时，`bit 3` = 已完成去皮，`bit 4` = WS2812 已初始化，`bit 5` = 重量标定参数有效，`bit 6` = LED 颜色 NVS 持久化可用。未定义位必须为 `0`。

上位机应在建立连接后立即请求一次状态；连续刷新频率不得高于 10 Hz。若 `sample_age_ms` 大于 1000 ms，或设置了 HX711 读取超时位，UI 必须明确显示重量数据已过期/故障，不能将旧值显示为实时重量。

### `SET_LED_COLOR`

仅在握手成功后允许发送。请求负载固定为 3 字节，依次为 `red`、`green`、`blue`（均为 `u8`，范围 `0..255`）。成功响应负载长度为 `0`。

该命令始终将相同的颜色写入左右两个灯条：左灯条连接 GPIO0、右灯条连接 GPIO21，每条均为 8 颗 WS2812。上位机默认提供蓝色 `#0000FF`、红色 `#FF0000` 与紫色 `#8000FF` 三个预设，也可发送任意自定义 RGB 值；协议不支持为左右灯条设置不同颜色。

设备首次运行或未找到有效颜色配置时默认显示紫色 `#8000FF`。每次 `SET_LED_COLOR` 成功后，设备将 RGB 值写入 NVS；后续重启会恢复该颜色。若 NVS 无法访问或写入，状态的 LED 持久化位会清除，且 `SET_LED_COLOR` 返回 `INTERNAL_ERROR`，不会报告设置成功。

## 错误响应

错误帧 `type=0xFF`，并使用原请求的 `sequence`。负载为：

| 偏移 | 字段 | 类型 | 说明 |
| --- | --- | --- | --- |
| 0 | `command` | `u8` | 引发错误的请求命令号 |
| 1 | `error_code` | `u8` | 错误码 |

错误码：

| 值 | 名称 | 含义 |
| --- | --- | --- |
| `0x01` | `UNSUPPORTED_VERSION` | 不支持请求的协议版本 |
| `0x02` | `UNSUPPORTED_COMMAND` | 命令未定义 |
| `0x03` | `INVALID_PAYLOAD` | 负载长度或字段非法 |
| `0x04` | `NOT_CONNECTED` | 需握手的命令在握手前调用 |
| `0x05` | `BUSY` | 下位机无法在协议时限内接收该操作 |
| `0x06` | `INTERNAL_ERROR` | 下位机内部故障；固件须记录具体原因 |

无效帧本身没有可信 `sequence`，不得尝试构造错误响应。

## 上位机连接流程

```text
选择串口 → 打开 115200 8N1 → 等待并清空输入
        → GET_DEVICE_INFO(sequence, client_nonce)
        → 校验 0x81、sequence、nonce、CRC 和协议版本
        → 标记已连接并显示 device_id / 固件版本 / capabilities
        → GET_STATUS(sequence + 1) → 校验 0x82 → 显示状态
```

任何读取超时、端口 I/O 错误、解码错误或响应关联失败都会使本次请求失败。连续两次状态请求失败时，上位机必须断开并要求用户重新选择/连接，而不是继续展示过期状态。

## 实现与测试要求

- 固件和上位机各自必须有 COBS、CRC、长度限制、帧关联和错误帧的单元测试。
- 集成测试至少覆盖：正常握手、错误 `sequence`、错误 `client_nonce`、CRC 损坏、截断帧、未知命令，以及 HX711 无有效样本的状态响应。
- 上位机在 UI 中显示的连接成功必须来自完成的协议握手，不能由“成功打开 COM 端口”替代。
